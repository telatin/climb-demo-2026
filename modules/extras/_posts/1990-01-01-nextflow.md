## What is Nextflow?

A bioinformatics analysis often requires several programs.

For example, we might first check the quality of our reads, remove unwanted sequences, run an assembler and finally analyse the resulting genomes. We could run all these commands manually, but this quickly becomes difficult when we have many samples.

**Nextflow** is a workflow manager. It allows us to describe the different steps of an analysis as a **pipeline**, and then takes care of running them in the correct order.

This has two important advantages.

First, it helps with **reproducibility**. The pipeline records how the analysis should be performed, and Nextflow can run each step using a specific software container. This makes it much easier to repeat the same analysis later or on another computer.

Second, Nextflow takes care of **orchestration**. If several jobs can run independently, Nextflow can run them at the same time rather than waiting for one job to finish before starting the next one.

For example, if we have 20 samples, a quality-control step does not necessarily need to process them one after another. Nextflow can submit several jobs in parallel, depending on the available resources.

In other words, instead of manually managing many commands and jobs, we describe the workflow and let Nextflow organise the work.

## nf-core pipelines

We do not always need to write a Nextflow pipeline ourselves.

[nf-core](https://nf-co.re/) is a community project providing a large collection of **curated Nextflow pipelines** for common bioinformatics analyses.

There are pipelines for RNA sequencing, metagenomics, variant calling, genome assembly and many other tasks.

A simple example is `nf-core/fetchngs`. Given accession numbers from repositories such as ENA or SRA, it can retrieve the corresponding sequencing reads and metadata.

For example, a typical command looks like:

```bash
nextflow run nf-core/fetchngs \
  --input accessions.csv \
  --outdir results/
```

Here Nextflow downloads the `nf-core/fetchngs` workflow and takes care of running its different processes.

We will see some examples later.

## Nextflow on CLIMB

CLIMB uses **Kubernetes** to manage its computing infrastructure.

When you launch a JupyterLab environment on CLIMB, Kubernetes creates a **pod** for it. You can think of a pod, for now, as a small isolated computing environment running somewhere in the CLIMB cluster.

Nextflow is already installed and configured in CLIMB JupyterLab environments.

More importantly, Nextflow is configured to use the CLIMB Kubernetes cluster.

When a pipeline needs to run a process, Nextflow can create a **new Kubernetes pod** for that job:

```text
JupyterLab pod
     |
     +--- Nextflow
             |
             +--- job pod
             +--- job pod
             +--- job pod
             +--- ...
```

These pods can run independently and in parallel. When a job has finished, its pod is no longer needed.

This means that the JupyterLab environment is where we **start and control** the pipeline, but the computational work does not all have to happen inside that JupyterLab pod.

Nextflow and Kubernetes take care of distributing the jobs across the available CLIMB resources.

> 💡 You do not need to configure Kubernetes yourself. CLIMB has already configured Nextflow to use the Kubernetes executor.

## Using S3 storage

Nextflow on CLIMB is also configured to work with CLIMB **S3 buckets**.

This is particularly useful for large sequencing datasets. Instead of first copying everything into your JupyterLab environment, a pipeline can use an S3 location directly as an input or output when the pipeline supports it.

For example, an output directory could be:

```text
s3://team-name-bucket-name/results/
```

and we could use it with an nf-core pipeline:

```bash
nextflow run nf-core/fetchngs \
  --input accessions.csv \
  --outdir s3://team-name-bucket-name/fetchngs/
```

CLIMB automatically provides the S3 configuration and credentials to your JupyterLab environment, so normally there is no additional setup required.

This combination is quite powerful: **Nextflow describes the analysis, Kubernetes provides the computing resources, and S3 provides scalable storage for the data.**
