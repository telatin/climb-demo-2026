## Before you start

You need RStudio and an R installation with the `tidyverse` package. You also
need `table.tsv` in the working directory used by the example. In RStudio,
the current working directory is the directory from which relative paths such
as `"table.tsv"` are interpreted.

Open the `.Rmd` file in RStudio and look at the four main areas:

* the **Source** pane contains the R Markdown document;
* the **Console** runs R commands interactively;
* the **Environment** pane shows objects created during the session;
* the **Files**, **Plots** and **Help** tabs show files, figures and
  documentation.

## R Markdown documents

An R Markdown document combines prose, R code and output. Text is written in
Markdown, while code is placed in *chunks*:

````markdown
```{r}
summary(c(1, 2, 3))
```
````

Clicking **Run** on a chunk sends its code to the R console. Clicking **Knit**
executes the document from beginning to end and creates a report (HTML in the
example). This is different from an interactive session: knitting starts with
a clean environment, so the report does not accidentally depend on objects
created in an unrelated experiment.

The setup chunk in `explore_table.Rmd` loads `tidyverse` and sets options for
the figures. The `include=FALSE` option runs the setup code without displaying
that code or its output in the final report.

## The data and tidy tables

The example table contains taxa as rows, sequencing samples as columns and raw
abundance counts as values. `read_tsv()` from the `readr` package imports this
tab-separated file into a tibble, the tidyverse version of a data frame:

```r
library(tidyverse)

counts <- read_tsv("table.tsv") |>
  rename(Taxon = `#Taxon`)
```

The pipe operator `|>` passes the result on to the next operation. Reading the
data and renaming the first column can therefore be read from left to right.
The backticks are needed because the original column name starts with `#`.

The imported table is *wide*: there is one column for every sample. For many
operations, and especially for `ggplot2`, it is easier to use *tidy* or *long*
format, with one row for each taxon and sample combination:

```r
tidy_counts <- counts |>
  pivot_longer(
    cols = -Taxon,
    names_to = "Sample",
    values_to = "Count"
  )
```

`pivot_longer()` keeps `Taxon` fixed and stacks the sample columns into
`Sample` and `Count`. The table becomes longer, but each observation has a
clear meaning. This makes filtering, grouping and plotting more consistent.

## Transforming biological labels

The taxon column contains full lineages such as
`k__Bacteria,p__Firmicutes,...,g__Lactobacillus`. The report uses string
functions to extract useful ranks such as phylum and genus. For example,
`str_extract()` finds the part beginning with `g__`, and `str_remove()` removes
that prefix. `replace_na()` labels taxa where the rank is missing.

This is a common pattern in bioinformatics: preserve the original identifier,
then create extra columns containing the parts needed for a particular
analysis. It is safer than replacing the original labels.

## Summarise before plotting

The report calculates library sizes by adding counts for each sample. It also
groups taxa by phylum and genus. In tidyverse code, functions such as
`summarise()`, `arrange()` and `slice_head()` express these operations directly:

```r
library_sizes <- tidy_counts |>
  summarise(Total = sum(Count), .by = Sample) |>
  arrange(desc(Total))
```

The **library size** is the total number of counts in a sample. In this data,
library sizes differ substantially, so raw counts are not directly comparable
between samples. The report therefore also calculates relative abundance,
expressed as a percentage of the counts within each sample.

Grouping by a taxonomic rank gives a broader view of the community. For
example, adding all genera belonging to the same phylum can show whether the
community is dominated by Firmicutes or Proteobacteria without displaying
every individual taxon.

## Visualising the table with ggplot2

`ggplot2` builds plots by mapping columns to visual properties. A simple plot
of library sizes uses the sample name on the x-axis and the total on the
y-axis:

```r
ggplot(library_sizes, aes(x = Sample, y = Total)) +
  geom_col() +
  scale_y_log10()
```

`aes()` defines the mappings and `geom_col()` draws bars whose heights are the
values already present in `Total`. `scale_y_log10()` is useful when library
sizes span several orders of magnitude. Other plots in the report use
horizontal bars for the most abundant genera and stacked bars for relative
community composition.

The plot code is deliberately separate from the data preparation. We can
change colours, labels or scales without changing the count calculations.

## Run the example

Open `explore_table.Rmd`, select a code chunk and click the green arrow to run
it. Watch the objects appear in the Environment pane and the figures appear in
the Plots pane. Then use **Knit** to produce the complete HTML report.

If the import fails, check the Files pane and the working directory first. If a
package is missing, install it in the R environment used by RStudio and rerun
the setup chunk. The report should be run from top to bottom when knitted,
because later chunks use objects created by earlier chunks.

The Python notebooks and this R Markdown report use the same table, but they
demonstrate different ways of working. Python notebooks are interactive
documents with executable cells; R Markdown reports are designed to be woven
into a reproducible document. Both approaches keep analysis code close to its
explanation and make exploratory results easier to share.
