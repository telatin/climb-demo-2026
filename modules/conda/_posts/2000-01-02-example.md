> This example is designed to showcase how to use CLIMB Environments,
> it's not meant to be treated as a bioinformatics tutorial: we will skip QC steps
> and ignore any undestanding of the dataset or biological questions


In this tutorial we will:

* download Nanopore reads from a bacterial isolate
* perform a quick QC of the raw reads
* assemble *de novo* the reads to produce an assembly draft

## Creating environments

We can add several tools in a single environment, but large environments can become difficult to manage
and it's better to try to use modula environments (for example, mapping tools and QC tools are used for several analyses).

```bash
mamba create -n qc  --yes \
  "seqfu>=1.28" "fastp>=1.0" "nanoplot" "fastp" "fastplong"

mamba create -n datasets --yes \
  sra-tools   ncbi-datasets-cli

mamba create -n denovo --yes \
  flye
```
## Downloading the raw reads

Activate the `datasets` environment and use `fasterq-dump` (from `sra-tools`) to download the Nanopore reads for a bacterial isolate:

```bash
conda activate datasets

mkdir raw-reads
fasterq-dump -O raw-reads -t 4 --verbose ERR17175504
```

- `-O raw-reads` writes the output into the `raw-reads/` folder
- `-t 4` uses 4 threads
- `--verbose` reports progress, ending with a summary such as:

```text
spots read      : 385,998
reads read      : 385,998
reads written   : 385,998
```

This produces `raw-reads/ERR17175504.fastq`.

## A small QC

Switch to the `qc` environment and run NanoPlot on the downloaded reads:

```bash
conda deactivate
conda activate qc

NanoPlot --fastq raw-reads/ERR17175504.fastq -o nanoplot
```

This creates a `nanoplot/` folder with several QC plots. From the JupyterLab file browser, open:

```text
nanoplot/LengthvsQualityScatterPlot_dot.html
```

:warning: JupyterLab will ask you to **Trust HTML** before the plot renders — click it to view the plot.

## Running the assembly

With the `denovo` environment (created earlier), assemble the reads *de novo* with Flye:

```bash
conda deactivate
conda activate denovo

flye --nano-raw raw-reads/ERR17175504.fastq \
  --genome-size 4M \
  --out-dir ecoli-ctgs \
  --threads 4
```

- `--nano-raw` tells Flye the input is uncorrected Nanopore reads
- `--genome-size 4M` gives Flye an expected genome size (~4 Mb, typical for a bacterial isolate)
- `--out-dir ecoli-ctgs` is where the assembly and logs will be written
- `--threads 4` matches the threads used earlier

The draft assembly will appear as `ecoli-ctgs/assembly.fasta`.

```bash
conda deactivate
conda activate qc

seqfu stats -ntb ecoli-ctgs/assembly.fasta
```

We can check that we produced 4 contigs, the largest being 5Mb (most of the assembly):
