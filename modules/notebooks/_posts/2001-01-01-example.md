## Before you start

You need:

* access to JupyterLab;
* a Conda environment containing `ipykernel`, `pandas`, `numpy` and
  `matplotlib`;
* the example files `explore_simple.ipynb`, `explore_table.ipynb` and
  `table.tsv`.

The Conda tutorial explains how to create such an environment. In particular,
`ipykernel` is required for an environment to appear as a Python notebook
kernel. For example, an environment for these notebooks could be created with:

```bash
mamba create -n notebooks \
  ipykernel pandas numpy matplotlib-base
```

Activate it when using a terminal:

```bash
conda activate notebooks
```

The environment does not need to be activated in the terminal for JupyterLab
to use it, but the environment must contain `ipykernel` and the packages used
by the notebook.

## What is a notebook?

A notebook is saved as a file ending in `.ipynb`. It contains *cells*. A cell
can contain either Markdown, which is used for explanations, or code, which is
sent to a programming language kernel.

The **kernel** is the running Python process behind the notebook. It remembers
variables between cells. For example, if one cell creates a variable called
`df`, a later cell can use `df` without reading the file again.

This memory is useful, but it can also be surprising. Cells do not have to be
run from top to bottom. If you change an earlier cell, rerun it and then rerun
the cells that depend on it. The menu option **Kernel > Restart Kernel and Run
All Cells** is a useful way to check that a notebook works from a clean start.

## Open a notebook in JupyterLab

Open the JupyterLab file browser on the left and navigate to the directory
containing the example files. Double-click `explore_simple.ipynb`.

The notebook opens in the main work area. At the top, JupyterLab shows the
kernel name. If it says `No Kernel`, or if it names an environment without
`pandas`, select **Kernel > Change Kernel...** and choose the Conda environment
created for notebooks.

The two example notebooks expect `table.tsv` to be in the same directory as
the notebook. This is because their code uses the relative filename
`"table.tsv"`. A relative path is interpreted from the notebook's working
directory, not from an arbitrary directory on your computer.

:warning: If you move a notebook away from `table.tsv`, the code will fail with
`FileNotFoundError`. Either move the files together or change the path in the
`pd.read_csv()` cell.

## Run the first cell

Click the first code cell in `explore_simple.ipynb` and press **Shift+Enter**.
This runs the cell and moves to the next one. You can also click the play
button in the toolbar.

The first code cell imports pandas and reads the tab-separated table:

```python
import pandas as pd

df = pd.read_csv("table.tsv", sep="\t", index_col=0)
df.index.name = "Taxon"
df.head()
```

`import pandas as pd` makes the pandas library available under the short name
`pd`, which is the usual convention. `read_csv()` reads comma-separated files
by default, so `sep="\t"` is needed for this TSV file. The `index_col=0`
argument uses the first column, containing taxon names, as row labels.

The final expression, `df.head()`, is displayed automatically by JupyterLab.
In a normal Python script we would usually write `print(df.head())`. Notebook
cells display the value of the final expression in a convenient table.

The output has taxa as rows and sequencing samples as columns. The values are
raw abundance counts. Because there are 29 samples, pandas hides some columns
in the middle of the display.

## Inspect the table

Before analysing data, we should check its shape and labels. Run the next
inspection cell, or try these expressions in a new code cell:

```python
df.shape
df.columns[:3]
df.index[:2]
df.dtypes.unique()
```

`df.shape` returns a pair in the order `(rows, columns)`. For this example the
answer is `(102, 29)`: 102 taxa and 29 samples. `df.columns` contains sample
names, while `df.index` contains the taxon names. The values are integer counts,
reported as `int64` by pandas.

It is also possible to use `print()` when we want several results from one
cell:

```python
print("Shape:", df.shape)
print("First sample:", df.columns[0])
print("First taxon:", df.index[0])
```

Notice the square brackets in `df.columns[0]`: Python uses position `0` for
the first item.

## Select and filter data

Selecting a column gives us one sample as a pandas `Series`:

```python
sample = df["ERR17070056"]
sample.head()
```

To select by position, use `iloc`. To select by a known row or column label,
use `loc`:

```python
# Third row and second column, using zero-based positions
df.iloc[2, 1]

# A value selected by taxon and sample names
df.loc["u__unclassified", "ERR17070056"]
```

Label-based selection is often safer in an analysis because it does not depend
on the current order of rows and columns.

We can filter the sample using a boolean mask. The comparison is applied to
every value in the Series and produces `True` or `False` for every taxon:

```python
mask = sample > 1000
print("Taxa above 1000 counts:", mask.sum())
sample[mask]
```

`sample[mask]` keeps only the rows where the mask is `True`. To combine two
conditions, use `&` for *and* and `|` for *or*. Put each comparison in
parentheses:

```python
both = (df["ERR17070056"] > 1000) & (df["ERR17070057"] > 1000)
df.index[both]
```

:warning: Python's `and` and `or` do not perform this element-by-element
operation on pandas objects. Use `&` and `|` here.

## Calculate relative abundance

Samples can contain different numbers of total counts. First calculate the
library size of every sample:

```python
sample_totals = df.sum(axis=0)
sample_totals.sort_values().head()
```

With `axis=0`, pandas collapses the rows and returns one total per column. The
smallest libraries in this example are much smaller than the largest ones.

We can convert one sample from counts to percentages by dividing by its total:

```python
relative = sample / sample_totals["ERR17070056"] * 100
relative.sort_values(ascending=False).head().round(2)
```

This does not change the original `df`; it creates a new Series. Relative
abundance is useful for comparing composition, but it does not remove all
statistical problems caused by sequencing depth or compositional data. More
advanced microbiome analyses require methods designed for those issues.

## Work with taxonomic labels

The taxon names are comma-separated lineages. We can extract the genus from
each label using a regular expression:

```python
genus = (
    df.index.to_series()
      .str.extract(r"g__([^,]+)")[0]
      .fillna("unclassified")
      .rename("genus")
)

genus.head()
```

The pattern `g__([^,]+)` looks for `g__` and captures the characters up to the
next comma. `fillna()` gives a name to rows such as `u__unclassified`, which do
not contain a genus.

Several rows may belong to the same genus. We can add those rows together:

```python
by_genus = df.groupby(genus).sum()
top10 = by_genus.sum(axis=1).sort_values(ascending=False).head(10)
top10
```

The result shows the most abundant genera across all samples. In this data,
`Lactobacillus` is the most abundant genus. The complete simple workflow is in
`explore_simple.ipynb`, including reshaping the table to a long format and
writing a result to `top_genera.csv`.

## Make plots with the second notebook

Open `explore_table.ipynb` in a new tab. It repeats the loading and grouping
steps, then uses `matplotlib` to visualise the results. Run the cells from top
to bottom with **Shift+Enter**. The later cells use objects such as
`sample_totals`, `by_phylum` and `by_genus` created earlier, so skipping cells
will produce `NameError` messages.

The first plot shows library sizes:

```python
fig, ax = plt.subplots(figsize=(12, 4))
sample_totals.plot(kind="bar", ax=ax, color="steelblue")
ax.set_yscale("log")
ax.set_ylabel("Total counts (log scale)")
plt.tight_layout()
plt.show()
```

The logarithmic y-axis is important here. A few samples have far fewer counts
than the others. On a linear scale, the smaller bars would be almost invisible.

The notebook also plots the most abundant genera and a stacked bar chart of
relative abundance. In a stacked chart, each sample is normalised to 100%, so
we can compare composition rather than total sequencing depth.

Finally, it creates a heatmap of phylum-level abundance. The `log1p` transform,
`log(1 + x)`, makes rare phyla visible without changing zero values into
missing values. Try changing the colour map from `"viridis"` to `"plasma"` and
rerun the cell.

## Save and export results

Notebook outputs are saved in the `.ipynb` file when you save it with
**File > Save Notebook** or `Ctrl+S` (`Cmd+S` on macOS). Saving preserves the
code, Markdown and usually the displayed outputs.

The notebook is not the same thing as a finished data file. For example, the
simple notebook writes the top genera to a separate CSV file:

```python
top10.rename("total_counts").to_csv(
    "top_genera.csv",
    index_label="genus",
)
```

This makes the result easy to use in another program. It is good practice to
rerun the notebook from a fresh kernel before sharing it, so that the saved
outputs correspond to the code and not to an earlier experiment.

## Common problems

**`No module named pandas`** means that the selected kernel does not contain
pandas. Change the kernel to the environment created for this exercise, or
install pandas into that environment with Conda.

**`FileNotFoundError: table.tsv`** usually means that the table is not beside
the notebook, or that the notebook's current directory is different from what
you expected. Check the JupyterLab file browser and the path in
`pd.read_csv()`.

**`NameError: name 'df' is not defined`** means that the cell creating `df` has
not run in the current kernel. Run the earlier cells, or restart the kernel
and use **Run All Cells**.

**The output is too wide** is normal for a table with many samples. Use a
smaller slice such as `df.iloc[:5, :5]`, or inspect only selected columns.

## Try it yourself

The supplied notebooks are starting points rather than locked examples. Try
one of these small changes:

* Count how many taxa have non-zero counts in each sample.
* Change the filter from `> 1000` to `> 10000` and compare the result.
* Plot the top 5 genera instead of the top 10.
* Add `ax.set_xlabel("Sample")` to the library-size plot.

The useful habit is to change one cell, run it, and inspect the result. That is
the main strength of a notebook: we can explore a biological question in small
steps while keeping the commands and their outputs together.
